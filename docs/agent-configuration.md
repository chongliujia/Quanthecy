# 模拟实验室：专业化 Agent 配置

本轮优先级是角色、模型、协作流程和风控的配置体验。目标是让用户在运行前清楚每个角色承担什么职责、依赖哪些输入、实际使用哪个模型，以及哪些约束由系统执行。

## 本轮已实现

入口：**模拟交易实验室 → 我的助手 → 配置总览**。

- 团队总览列出每个节点的角色、直接上游、输出要求和实验输出上限；可直接进入该节点的研究方法、输入连接或模型配置。
- 展示真实工作区模型、每轮调用数、当日剩余工作区调用数，以及实验各节点输出上限的总和。总和是输出预算上限，不是预计 token 用量或美元费用。
- 五类角色分别提供可追加到 Prompt 的方法清单：量化信号质量、事件来源与时间、合约结算语义、风险反证、结构化入场评审。追加保留既有指令，支持独立撤销；清单只是可编辑的研究方法，不是效果已验证的策略。
- 节点增加可选 `max_output_tokens`，留空继承工作区设置，支持 256–65,536 的整数。试运行实际值为节点与工作区上限中的较小值；自动模拟评审再受已有的每次 2,048 token 上限限制。
- LangGraph 执行适配器将实际值传入服务商连接，每步保存模型、提供方、配置修订号和实际输出上限。运行详情展示实际值；旧记录没有这些字段时不推断补齐。
- 风控区集中展示可编辑的 15 分钟信号门槛及服务器提供的新实验固定规则：市场与事件资金上限、最大价差、报价时效和策略持仓时限。

所有节点目前仍然共用工作区模型。模型设置链接不会伪装成节点独立选模。节点 token 配置随草稿、发布版本及任务图快照保存，后续草稿修改不改变已发布版本或排队任务。工作区模型设置变化仍按既有规则使未完成任务停止；发布助手版本并不永久锁定工作区模型。

节点输出限额过低可能导致输出截断、校验失败。推理 token 是否计入输出额度依赖服务商；显示值不保证模型能生成同等长度的报告。

输入连接表达的是结论依赖：每个节点都获得冻结市场证据，额外只接收明确连接的上游结论。无上游节点独立分析，不读取其他分析者结论。现有强制路径仍为分析节点 → 风险复核 → 入场评审；执行顺序、单工作区活动任务限制、额度预留和失败处理保持原语义。

固定规则来自只读、组织鉴权的 `GET /api/v1/organizations/{id}/paper/policy`，不创建实验、不发布助手、不调用模型。它描述新实验默认规则；已有实验以自己的冻结 `settings` 为准。资金上限和执行检查继续由确定性代码实施，Prompt 不能放宽。

## 已保存的模型连接

模型设置现在按工作区、协议和规范化后的完整 API 地址分别保存连接档案。切换本地与远程时，不再要求删除原连接密钥。通过「已保存的连接」恢复模型名、输出上限、本地上下文和推理选项，点击保存后才切换当前连接。

服务端在同一组织锁与事务内保留旧连接并保存目标连接，只取目标地址和协议对应的密钥；新地址不继承旧密钥。前端只获取 `has_api_key`，不获取明文或密文。清除密钥只作用于当前所选连接，其他连接保留。工作区启用状态和每日调用额度仍是全局设置，不随连接档案隐式恢复。

迁移 `agents.0007_saved_model_connections` 原样复制现有配置中的密文，不解密、不轮换密钥、不切换当前配置，也不修改启用状态。旧版本已经删除的密钥无法由迁移恢复，需要用户重新输入。修改当前配置继续取消未完成任务，保留历史运行。

## 下一阶段：节点独立模型

连接档案已实现，后续再允许角色显式绑定其中一个连接或继承默认。Django 继续管理加密凭据和组织权限，不把连接密钥放入图、前端或运行记录。

实施前需要一起解决：

1. 每个节点冻结连接 ID、模型 ID、配置修订和输出预算；运行记录能准确说明实际使用的模型。
2. 连接修改、停用或权限撤销后停止后续调用；保留已经完成的步骤和尝试用量。
3. 按整个图预留工作区调用额度；失败不能悄悄切换到另一个模型或增加重试次数。
4. 提供跨组织引用、版本冻结、取消和服务商异常测试；没有用户启动试运行或实验时不产生模型调用。

不同模型可以提供不同视角，但不能仅凭模型数量声称独立性或效果提升。

## 下一阶段：协作与风控策略

- 提供“精简分析”“事件研究”“合约审查”等团队模板，每个模板说明角色、输入依赖和调用数。复制后可修改，发布后不可变。模板说明不宣传收益。
- 增加版本差异查看，分别展示 Prompt、启用的 Skills、依赖、模型和规则变化，减少仅靠版本名称辨认实验的负担。
- 为实验加入独立的风险策略版本。先允许在平台范围内收紧单市场／事件投入、价差和报价时效；在候选生成、订单创建及成交检查上统一执行，不能只改前端或模型提示词。
- 新策略进入新实验版本，历史账户继续遵循冻结规则。暂停、保留持仓、估值与结算语义须在界面明确。

## 用结果验证配置的价值

当前 paper-v3 能比较多个助手账户，但队列、候选入场门槛、持仓和拒绝结果都可能改变实际样本。配置专业化之后，应补上：

- 共同机会视图：按同一市场、观测和研究截止时间对齐各版本，分别显示允许、拒绝、等待、失败、排队、过期与实际成交。
- 角色贡献实验：同条件比较精简团队与加入特定角色后的团队；不把改动入场门槛和改动角色混为同一种实验变量。
- 决策复盘：信号与冻结证据 → 上游发现 → 风险质疑 → 入场评审 → 最新价格复验 → 模拟订单，附版本和步骤用量。
- 同期展示收益、回撤、费用、可定价覆盖、成交样本数、处理延迟及模型用量。未取得模型账单时费用保持未知。

当前没有实现共同上下文的批量配对评估、角色增益归因、逐节点独立模型、预测校准或自动风控优化。后续功能应有独立验收，不能把本轮配置界面当作这些能力已经完成。

## 画布坐标修复

原先节点在前端拖拽与后端 schema 中都限制为非负坐标。图居中显示后，画布原点左侧虽然有可见空间，节点却无法进入。现在鼠标、键盘、节点添加与保存均支持正负坐标，范围为各轴 ±100,000；新增节点优先在当前视野附近寻找空位。此修改不改变连线或分析依赖。已有图无需改写，自动整理和撤销继续可用。

## 兼容性与验证

- 节点预算和步骤使用已有 JSON 字段。未设置节点输出限额时不序列化新增字段，旧图哈希保持不变。连接档案新增 PostgreSQL 表，部署前备份、执行 Django 迁移，再更新后端及模型／模拟 worker。
- 草稿、版本和任务继续执行组织隔离、VIEWER 只读、乐观锁、会话与 CSRF 约束。
- 测试覆盖真实执行适配器收到限额、工作区与实验上限、发布／排队后修改草稿、API 步骤记录、非法输入和旧图哈希。
- 浏览器使用独立上下文与拦截的界面测试数据检查深浅色、390/1440/1920px、角色清单追加及预算保存；没有写入用户助手或发送真实模型请求。
- 连接测试覆盖本地与远程来回切换、原密文保留、地址／协议／组织隔离、清除单个连接密钥以及迁移保留已有配置。画布测试覆盖负坐标保存与实际鼠标左拖越过原点。
