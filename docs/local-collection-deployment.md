# 本机持续采集部署

2026-09-17 在现有机器上恢复部署，保留原有 PostgreSQL、ClickHouse、Redis 和采集器日志卷，并应用当前版本的数据库迁移。前端、后端与 Rust 采集器均重新构建为运行镜像。

## 访问与运行条件

- 工作台：<http://localhost:3000>，可注册或使用已有账号登录。
- 运营后台：<http://localhost:8000/admin/>，平台管理员已按账号所有者的要求配置并验证登录。
- 市场发现：<http://localhost:8000/admin/platform/directory/>。
- 后端依赖检查：<http://localhost:8000/ready>。
- 采集器内部状态：<http://127.0.0.1:8080/status>。

这是仅绑定本机地址的部署。Compose 当前仍使用 Django 本地设置，不能直接作为公网生产配置使用。本次没有配置域名、HTTPS 或远程服务器。

所有常驻服务使用 `restart: unless-stopped`；`migrate` 是执行完退出的一次性服务。持续采集需要宿主机、Docker 和本机代理保持运行，休眠或关闭机器会造成观测中断。自动重启策略不会主动恢复手动停止的容器。

本机使用未纳入版本控制的 `compose.override.yaml`：采集器和新闻进程通过 `127.0.0.1:7897` 代理访问外部来源。数据库辅助端口仅绑定回环地址。凭据保留在原有 `.env`，不要把它加入版本控制。

2026-09-18 接入宿主机上的本地模型服务 `http://127.0.0.1:8001/v1`。本机覆盖文件为 Agent 工作进程启用宿主机网络，模型请求直连服务，交易所与新闻的代理配置保持独立。模型配置由工作区所有者在前端管理，详细设置及可复用覆盖文件见[本地模型说明](research-terminal.md#local--offline-inference)。

## 日常检查与恢复

在项目根目录执行；显式指定文件，保持本次运行配置，不加入热更新开发覆盖文件：

```sh
docker compose -f compose.yaml -f compose.override.yaml ps --all
docker compose -f compose.yaml -f compose.override.yaml logs --since 10m --tail 100 market-data worker news-worker
```

采集成功需要同时确认新批次入库、各来源最近观测时间前进，以及分析工作进程完成同步。容器 `healthy` 或采集器进程存活本身不能证明每个目标都在成功采集。

使用已有镜像恢复服务：

```sh
docker compose -f compose.yaml -f compose.override.yaml up -d --no-build --wait
```

当前以 PostgreSQL 中的后台计划为准，修改 `.env` 的市场名单或重启容器不会覆盖已启用的托管计划。后台变更由工作进程发布，并由采集器动态应用，通常不需要重启。不要通过清空采集器日志卷来强制切换配置。

## 数据保留

本次迁移前的 PostgreSQL 备份、采集器日志备份及名单修改前的环境文件保存在本机 `/tmp/quanthecy-deployment-20260917/`，包含敏感配置，不应上传或共享。它们只用于本次部署回退，临时目录不构成长久备份策略。ClickHouse 历史卷已保留，本次未制作其独立备份。

停止服务可使用 `docker compose -f compose.yaml -f compose.override.yaml stop`。不要使用 `down -v` 或删除上述命名卷，否则会丢失历史数据和采集恢复状态。
