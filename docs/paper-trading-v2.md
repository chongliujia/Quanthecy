# 自动评审模拟实验 — paper-v2

v2 补齐“合格信号 → 自动排队评审 → 重新检查 → 模拟成交 → 对照评估”。只读交易所公开数据，使用虚拟本金，不调用交易所下单接口。

## 使用

在同一工作区的 **模型设置** 配置并启用模型，然后打开 **模拟交易实验室**。已有 v1 实验时，可点击 **启动 v2 并保留 v1**。升级复用 v1 的固定市场范围和每账户初始本金，为 v2 创建新的动量、Agent 筛选、买入持有账户。v1 取消待成交订单、停止新开仓，保留全部账本和持仓，继续估值和确认结算。历史版本可从页面顶部切换查看，升级后不能恢复 v1 的新交易。

没有模型配置时，基线账户仍正常运行，Agent 区域显示“等待模型配置”。启用模型后，仍有效的候选机会与后续合格信号会自动进入评审；已过期机会不补做，也不会倒填成交。

## 独立入场评审

普通研究的 WATCH / INVESTIGATE 只代表研究优先级。v2 使用独立 `paper-review-v1` 提示词和严格结构化输出：

- `ALLOW`：允许在重新通过确定性检查后模拟入场。允许包含一般风险提示，不能包含阻断风险或缺失的关键证据。
- `REJECT`：必须给出有引用依据的阻断风险。
- `WAIT`：证据不足或结论不确定，继续等待本次候选机会结束。

输出包含理由、阻断风险、一般提示与缺失证据。每项事实/假设引用冻结上下文中的参考 ID；伪造引用、额外字段或不一致结论会验证失败。模型不计算仓位、收益或概率指标，不使用置信度当胜率，也不能覆盖资金和价格限制。

上下文基于信号当时的历史截止时间，包含可用的合约、量化指标和已观测证据，并加入精简的冻结入场参数。原始订单簿和完整候选快照保存以供检查，但不把百档深度直接塞入模型。第三方内容作为不可信证据处理，不允许模型调用工具或发出订单。

## 自动调用边界

- 同一候选机会仅对应一个 `PAPER_REVIEW` 任务，重复调度、重启和并发调度不会再次预留调用。
- 新候选产生于有效的动量买入条件；没有信号不调用模型。
- 同一市场候选间至少间隔 15 分钟；一次机会有效期 10 分钟。期间复用同一评审任务和报告。
- 默认每天最多预留 10 次自动评审，可在新建/升级时选择 1–20 次，此限制随实验冻结。还受模型设置的工作区每日总额度限制。按 UTC 自然日计数，失败和取消的预留也计入额度。
- 单次最多输出 2,048 token，同时受模型配置的更小上限约束。不自动更换或启用模型，不修改用户提供的连接信息，不自动重试失败请求。
- 复用现有 Agent 队列、运行租约和独立 Agent worker，工作区同时最多一个活动模型任务。手动研究占用队列时，自动候选先等待。
- 模型禁用、权限变化、额度耗尽、队列忙、上下文不足与调用失败均记录明确原因，不回退到无评审入场。
- 暂停实验会取消待评审/运行中的任务并阻止报告发布或用于交易。已发往服务商的请求可能仍产生费用，不能假定取消能够撤销计费。

在排队及模型调用前重新检查当前信号、观测新鲜度、合约规则和到期时间。报告发布前再次检查实验与配置状态。消费报告时重新检查入场条件、最新双边报价、费用、合约/结果身份、模型配置版本、资金与事件投入上限。当前买价与冻结买价相差超过 2 美分，或候选过期，报告失效。报告返回不会触发用旧价即时成交；新订单继续遵循后续订单簿、延迟和深度限制。

报告结果允许即时重新评估，即使新观测尚未到达：决策使用独立 REVIEW 阶段，在不修改原 SIGNAL 决策的前提下记录这次重验。数据库唯一约束与实验行锁共同阻止重复应用。

## 评估与解释

沿用 v1 的净值、已实现盈亏、浮盈、手续费、回撤和现金基准，并新增：

- 候选机会、完成报告、允许/拒绝/等待、失效和失败数量；这些指标存在交叉，例如报告允许后行情变化仍可失效。
- 共同机会的参与率：分母是已有动量基线实际买入成交的候选，分子是同一候选的 Agent 账户也实际成交的数量。它不是胜率，也不把未完成模型请求当作拒绝。
- 信号到报告完成的平均时间，以及任务入队到开始执行的平均排队时间。
- 已尝试服务商调用次数和服务商返回的输入/输出 token。失败请求不一定返回 token，用量可能不完整。
- 模型美元费用当前没有账单来源，显示“暂不可用”，不按零费用计，也不扣模拟账户本金。交易净值不包含模型服务费。
- 最近 20 个候选的处理原因与证据详情，保留冻结输入、结构化报告、引用上下文和用量。

三种策略的资金、手续费和模拟执行规则保持可对照。由于持仓状态、模型等待时间、拒绝和冷却不同，入场样本会有差异；参与率用于解释这些差异。不能仅凭交易减少或回撤较小就认定 Agent 有收益增益。v1 与 v2 开始时间不同，跨版本收益不是同期对照；优先比较同一 v2 实验内的账户。

## 实现与部署

`quanthecy.paper` 新增持久化 `Opportunity`，关联冻结信号、唯一 Agent 任务和最终应用决策。`Experiment.organization` 从一对一扩展为外键，数据库约束同一工作区每版本一个实验、最多一个正在运行的实验。所有历史查询、评审详情和修改接口都要求显式工作区上下文。

`POST /api/v1/organizations/{id}/paper/upgrade` 创建 v2；`GET .../paper?experiment_id={uuid}` 查看历史；`GET .../paper/opportunities/{uuid}` 检查评审证据。`PATCH .../paper` 可显式指定 `experiment_id`，避免历史页面误操作当前实验。模型任务不在 HTTP 请求或模拟账本事务中执行。

部署前备份 PostgreSQL，应用 `paper.0002_automatic_review_experiments`，再更新 backend、paper-worker、agent-worker 和 web。不要让旧版 Agent worker 消费新版 `PAPER_REVIEW` 任务。此次没有修改 Rust 采集器或 ClickHouse schema。

```sh
docker compose build backend web
docker compose stop paper-worker agent-worker
docker compose run --rm --no-deps migrate
docker compose up -d --no-deps backend paper-worker agent-worker web
```

暂停 v2 不会删除数据。不要回退数据库迁移去清除实验结果；恢复部署时保留已应用的新 schema。

## 验证记录

单元与回归测试覆盖：v1 历史保留、重复升级拒绝、租户隔离、VIEWER 写入拒绝、CSRF、没有信号不调用、模型禁用、工作区额度与队列竞争、并发调度只预留一次、普通风险提示可与 ALLOW 共存、阻断风险拒绝、WAIT 区分、信号/价格/规则/配置变化后的入场阻止、暂停与过期、引用验证、完整 Agent worker 的结构化评审发布，以及实际模拟成交后的参与率统计。

本次自动评审的服务商响应在测试中使用固定夹具；用户选择稍后自行配置模型，没有为验证而开启真实模型或产生付费请求。
